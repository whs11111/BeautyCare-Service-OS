## 处理步骤
1. 先判断用户本轮询问的是未发货、已发货运输中，还是明确显示签收却未收到；只采用相应分支，不把其他可能情况一起告诉用户。
2. 未发货：对等待表达歉意，说明需要核实发货安排和延迟原因；未发货时不得谈派送、代收、签收或丢件。
3. 已发货运输中：核实实际物流记录，只有查询结果有依据时才说明位置与预计送达；没有真实查询结果不得编造。
4. 用户明确反映签收未收到时，才引导确认代收情况，并核实签收记录；后续调查须以实际流程和权限为准。
5. 超过已确认的承诺时效时，主动致歉并核实补救方案；不能未经授权承诺催件已完成、补偿券或赔款。

## 回复要点
- 给具体信息（节点、时间），不要只说“请耐心等待”。
- 具体信息必须已有真实依据，没有时说明需要核实，不能为了显得具体而编造。
- 规范里的条件分支是内部判断依据，不是向用户罗列的回复模板。
